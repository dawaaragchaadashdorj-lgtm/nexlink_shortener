# Render deployment

## Prepared configuration

`render.yaml` creates one Node web service in Singapore with a 1 GB persistent disk.
It uses a paid compute plan. Check the Render cost summary before creating the service.
Auto-deploys are disabled; trigger a manual deploy after reviewing later changes.

The repository root is the folder containing `package.json` and `render.yaml`.
Do not set `rootDir: nexlink-shortener` when deploying this repository.

1. Connect the GitHub repository to Render.
2. Create a Blueprint using the `codex/render-deployment` branch and `render.yaml`.
3. Review the selected paid service and disk, then approve creation.
4. Wait until the service is healthy. Render assigns an HTTPS `onrender.com` URL.
5. Retrieve `CREATE_ACCESS_TOKEN` privately from the service's Environment settings.
6. Open the site, create a link, and enter that owner key when prompted. Do not share it with link recipients.

Only the owner can create links in production. Anyone with a short link can open it,
subject to that link's password and schedule. The owner key stays in memory in the
current browser tab; it is not saved to local storage or embedded in the site bundle.

## Environment

| Name | Value / purpose |
| --- | --- |
| `LINK_DATA_DIR` | `/var/data/links`; covered by the persistent disk |
| `CREATE_ACCESS_TOKEN` | Generated by Render; required for production creation |
| `NODE_ENV` | `production` |
| `RENDER_EXTERNAL_URL` | Automatically provided by Render; used for origin validation |
| `APP_ORIGIN` | Optional; set to `https://your-domain.com` when using a custom domain |

When `APP_ORIGIN` is set, create links from that domain. Other browser origins are rejected.
Do not put secret values in `NEXT_PUBLIC_*` variables, Git, chat messages, or screenshots.

## Verification after deployment

- `GET /api/health` must return `200` with `{"status":"ok"}`.
- Unauthenticated `POST /api/links` must return `401`.
- Create a link in the UI with the owner key and open it from another device.
- Check a password-protected link with both wrong and correct passwords.
- Restart the service and confirm the previously created link still redirects.
- Generate a QR code on the deployed site and scan it with a phone.

The health endpoint checks configuration and data-directory permissions. Test a real
link after deployment to confirm end-to-end writes and redirection.

## Operations

- Keep exactly one service instance: the filesystem and in-memory attempt limits are local to it.
- Creation is capped at 60 authorized requests/minute for the service. Password checks
  are capped at 10/minute per link and 120/minute overall. Limits reset on restart.
- For a larger public multi-user product, add account management and a shared database
  with durable quotas/rate limiting before opening link creation to everyone.
- Back up `/var/data/links`. Do not delete the persistent disk on redeploy.
- Localhost links and QR codes do not migrate automatically; create new ones on the deployed URL.
- Roll back a failed code release through Render's deploy history; retain the same disk.

Reference: https://render.com/docs/blueprint-spec and https://render.com/docs/disks
